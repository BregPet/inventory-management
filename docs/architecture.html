Factory Inventory Management System

Architecture overview: a Vue 3 single-page app on top of a FastAPI service that serves in-memory JSON mock data. There is no database and no authentication.

Architecture Tech stack Data flow Views and endpoints Known gaps

System architecture

Three layers on one machine. The browser talks to the API over HTTP with CORS fully open. The API reads JSON files once at startup and keeps them in memory.

Tech stack

Few dependencies on purpose: no UI kit, no chart library, no state library.

Frontend

Vue 3 + Vite 8

  • Composition API (setup())
  • vue-router 4, history mode, 6 routes
  • axios for HTTP
  • Custom SVG charts, CSS Grid layouts
  • Homegrown i18n: English and Japanese
Backend

Python 3.11+ / FastAPI

  • uvicorn on port 8001
  • Pydantic v2 response models
  • Auto-generated docs at /docs
  • Dependencies managed with uv
Data

JSON files, in memory

  • 7 files in server/data/
  • Read-only; nothing is persisted
  • Orders span the 12 months of 2025
  • 3 warehouses: San Francisco, London, Tokyo
Tooling

Dev and test

  • pytest + FastAPI TestClient (40 tests)
  • scripts/start.sh / stop.sh
  • No linter, type checker, or frontend tests
  • Playwright MCP for browser checks

Data flow: changing a filter

Example: the user picks Location "Tokyo" and Period "Q1-2025" on the Overview page.

  1. FilterBar updates shared refsuseFilters.js keeps the filter refs at module level, so every view sees the same selection, which is kept when you switch pages.
  2. The view reloads its dataDashboard watches the filters and calls getCurrentFilters(), which maps Location to warehouse and Period to month.
  3. api.js builds the requestValues set to 'all' are left out. Request: GET /api/dashboard/summary?warehouse=Tokyo&month=Q1-2025.
  4. FastAPI filters in memoryapply_filters() matches warehouse exactly and category/status case-insensitively. filter_by_month() expands Q1-2025 to 2025-01..03 and substring-matches order_date.
  5. The response is computed and validatedThe summary sums inventory value and counts low-stock items (quantity at or below reorder point) and pending orders (Processing or Backordered). List endpoints pass through Pydantic models.
  6. Vue derives the display stateRaw responses go into refs; KPIs, charts, and tables are computed properties built from them.

Known gaps

Places where the code currently disagrees with itself, as of 2026-11-03.

Missing backend routes. The client calls /api/tasks and /api/purchase-orders, but neither route exists, so loading tasks returns a 404 on every page. The PurchaseOrder models are already defined in main.py.
Missing component. Dashboard.vue renders <PurchaseOrderModal>, which does not exist.
Orphaned view. Backlog.vue exists but no route points to it.
Inconsistent API access. Reports.vue hardcodes http://localhost:8001 instead of using api.js.
Stale tooling. generate_data.py uses an old product catalog and overwrites orders.json. tests/README.md lists a test_orders.py that doesn't exist.
